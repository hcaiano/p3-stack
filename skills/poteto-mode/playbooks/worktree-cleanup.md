### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `<installed-poteto-mode>/scripts/worktree-audit.sh [-b <pr-base-ref>] --thread-activity <activity-export.json> [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.t3/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. Supply the audit's documented activity-snapshot input with a complete project-scoped T3 snapshot. Page `t3_thread_list` with `includeSubagents: true` across active and settled threads, read each thread's metadata and activity with `t3_thread_read`, and recover truncated text through its returned offsets. Include the thread ID, real activity timestamp, worktree binding and mentioned paths. Match worktree paths at boundaries and keep the source four-day recent-chat threshold and buckets. `t3_worktree_list` omits detached worktrees, so the script's `git worktree list` inventory remains authoritative. An incomplete activity snapshot does not prove a worktree is unused. The activity scan is slow; run it through a self-contained `delegate_task` with `mode: "async"`, then drain with `task_status` and stop with `task_cancel`.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan `delegate_task` subagents out with self-contained briefs and `mode: "async"` to read the threads with `t3_thread_read` and `t3_thread_search` and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, thread activity is bulk). A pinned chat spawns arena and repro trees into sibling worktrees via isolated `delegate_task` children, and those are in use even when their names never hit the sidebar. Use supported child isolation; `t3_thread_launch` is only for explicitly requested separate top-level conversations. Report a factual limitation if required isolation is unavailable.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, use `trash <path>`, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep. No T3 adapter for application-state backup and root-snapshot cache cleanup is established here; report that limitation rather than guessing a storage path.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
