# Subagents

Read this file in full before you spawn any subagent, as the playbook's chat or as a delegate. `../SKILL.md` holds the other rules.

Read `t3-execution.md` before selecting models or executing a playbook. It owns account selection, catalog option keys, automatic authorized missing-usage fallback and live T3 transport constraints. Resolve installed paths relative to this skill. A `t3_thread_launch` requires an explicit user request for separate top-level conversations; otherwise use supported child isolation or report the factual runtime limitation. Put the absolute path of poteto-mode's `SKILL.md` in every `poteto-agent` brief.

**Use `delegate_task` for any subagent you spawn inside a playbook step** (code-writing delegates, ad-hoc helpers). Open each brief with the installed `poteto-agent.md` path, which requires reading poteto-mode's `SKILL.md` in full before work. The chat that receives `/poteto-mode` runs the playbook. Never spawn a `poteto-agent` to run the playbook itself. Routed workflow skills (`how`, `why`, `interrogate`, `reflect`, `swarm`) set their own roles for diverse-model review. Respect what the skill prescribes, don't override to `poteto-agent`.

**Defaults for every `delegate_task` call.** `mode: "async"`, preserve MCP access, file pointers not inlined context, explicit model per named role (configurable via `/setup-pstack` in `pstack-models.md`). Defaults resolve from the bundled role values through `orchestrator_capabilities`. Every brief stands alone. T3 child agents get only the brief, never the parent's context. Retain task IDs, once nothing independent is left, end the turn until their completion notifications wake you, then read each result with `task_status`, and stop with `task_cancel`. Code delegates tier by difficulty. The hardest changes (cross-cutting design, gnarly concurrency, subtle algorithms) go to your strongest judgment model on the `hardest tasks` role, whether the task needs judgment on vague intent or is a precisely specified sequence of steps to execute to the letter. Trivial mechanical edits go to your fast code model. Per-role lines in `pstack-models.md` override these defaults and the model choices in the routed skills (`how`, `why`, `arena`, `swarm`, `architect`, `interrogate`, `reflect`). A role with no line keeps its default, and a role line of `inherit-parent` or `auto` runs that role on the parent chat model. Each code playbook's configured model comes from its line (`feature, refactoring`, `bug-fix`, `perf-issue`, or `hillclimb`), and the hardest changes read `hardest tasks`. Prose and judgment read `judgment and prose`.

**Effort comes from `pstack-models.md`.** A role runs at the effort that file gives it: its own line, an `# effort` header that names it, or the `# budget` line. Only when the file names none does the role take the bundled default, `xhigh`. Use the model's live catalog option for that level, or its highest supported value below it. Use fast mode only when the job is urgent, meaning CI or trunk is red or a person is blocked on the result right now. Otherwise use standard speed. Speed is the model's own live catalog option, such as a fast-mode toggle or a fast service tier. Set effort and speed explicitly on every spawn, because `delegate_task` inherits the parent's options. Use a fast variant with its own model ID only when the role's configuration names it. Verification runs on the `swarm workers` role's model and effort, with the model's fast option where its catalog has one. A role on `auto` or `inherit-parent` stays on the parent model.

You own every subagent's work. Review the diff and write your own summary, don't pass through what it said. A second opinion is the same prompt against a different model. Agreement is high-signal.

**Fresh subagents by default.** Give new work to a fresh subagent with consolidated scope, meaning the original brief, every later directive, and the prior agent's report and branch. This holds for a fix round, a follow-up, a retry, and the next queue item. Resume, message, or queue a follow-up on an existing subagent only when the new work strictly needs state that lives in that agent and is costly to move: its local checkout, its uncommitted changes, or a process it still runs, such as a dev server, a simulator, or a babysit watcher. A stop or hold order to a running agent is not reuse. A role such as a PR owner outlives its agent. Once that agent returns, a fresh agent takes the role's next round. Interrupt-chained resumes silently drop directives, so fire a fresh subagent with consolidated scope rather than trusting a "done" summary.
