# Subagents

Read this file in full before you spawn any subagent, as the playbook's chat or as a delegate. `../SKILL.md` holds the other rules.

Read `t3-execution.md` before selecting models or executing a playbook. It owns account selection, catalog option keys, automatic authorized missing-usage fallback and live T3 transport constraints. Resolve installed paths relative to this skill. A `t3_thread_launch` requires an explicit user request for separate top-level conversations; otherwise use supported child isolation or report the factual runtime limitation. Put the absolute path of poteto-mode's `SKILL.md` in every `poteto-agent` brief.

**Use `delegate_task` for any subagent you spawn inside a playbook step** (code-writing delegates, ad-hoc helpers). Open each brief with the installed `poteto-agent.md` path, which requires reading poteto-mode's `SKILL.md` in full before work. The chat that receives `/poteto-mode` runs the playbook. Never spawn a `poteto-agent` to run the playbook itself. Routed workflow skills (`how`, `why`, `interrogate`, `reflect`, `swarm`) set their own roles for diverse-model review. Respect what the skill prescribes, don't override to `poteto-agent`.

**Defaults for every `delegate_task` call.** `mode: "async"`, preserve MCP access, file pointers not inlined context, explicit model per named role (configurable via `/setup-pstack` in `pstack-models.md`). Defaults resolve from the bundled role values through `orchestrator_capabilities`. Every brief stands alone. T3 child agents get only the brief, never the parent's context. Retain task IDs, once nothing independent is left, end the turn until their completion notifications wake you, then read each result with `task_status`, and `task_cancel` only a child whose status is not terminal. Code delegates tier by difficulty. The hardest changes (cross-cutting design, gnarly concurrency, subtle algorithms) go to your strongest judgment model on the `hardest tasks` role, whether the task needs judgment on vague intent or is a precisely specified sequence of steps to execute to the letter. Trivial mechanical edits go to your fast code model. Per-role lines in `pstack-models.md` override these defaults and the model choices in the routed skills (`how`, `why`, `arena`, `swarm`, `architect`, `interrogate`, `reflect`). A role with no line keeps its default, and a role line of `inherit-parent` or `auto` runs that role on the parent chat model. Each code playbook's configured model comes from its line (`feature, refactoring`, `bug-fix`, `perf-issue`, or `hillclimb`), and the hardest changes read `hardest tasks`. Prose and judgment read `judgment and prose`.

**Effort comes from `pstack-models.md`.** A role runs at the effort that file gives it: an `# effort` header that names it, or else the `# budget` line. Only when the file names none does the role take the bundled default, `xhigh`. Use the model's live catalog option for that level. Where a playbook or routed skill says to pick the reasoning level for the job, the role sets it: use that role's effort. Every spawn runs at standard speed: set the model's live catalog speed option to its standard value, such as `fastMode: false` or the default service tier, and use the standard model ID, not a fast variant. Only the user turns fast mode on, by hand. Grok seats are exempt and keep their configured fast settings. Set effort and speed explicitly on every spawn, because `delegate_task` inherits the parent's options. Verification runs on the `swarm workers` role's model and effort, at standard speed. A role on `auto` or `inherit-parent` stays on the parent model.

You own every subagent's work. Review the diff and write your own summary in plain language, don't pass through what it said. A second opinion is the same prompt against a different model. Agreement is high-signal.

**Bounded code briefs.** A code delegate implements; it does not choose scope. Outside the `hardest tasks` role, its brief names the files to change, the approach already chosen, the acceptance commands, what is out of scope, and the PR it opens, if any. It adds no module, migration, dependency or PR the brief does not name, and reports the need instead. It starts no child tasks except the reviewers and panels a required skill starts, such as `review-it`, `no-comments` and `how`. A `hardest tasks` delegate chooses its own scope and approach. An owner is a delegate that carries a PR through merge, as in Autopilot-full and Autopilot-stack, fans out after the blocking phase, as in Feature, or coordinates other workers, as in Orchestrate. An owner reads the `judgment and prose` role, and these bounds apply to the briefs it writes.

**Fresh subagents by default.** Give new work to a fresh subagent with consolidated scope, meaning the original brief, every later directive, and the prior agent's report and branch. This holds for a fix round, a follow-up, a retry, and the next queue item. Resume, message, or queue a follow-up on an existing subagent only when the new work strictly needs state that lives in that agent and is costly to move: its local checkout, its uncommitted changes, or a process it still runs, such as a dev server, a simulator, or a babysit watcher. A stop or hold order to a running agent is not reuse. A role such as a PR owner outlives its agent. Once that agent returns, a fresh agent takes the role's next round. Interrupt-chained resumes silently drop directives, so fire a fresh subagent with consolidated scope rather than trusting a "done" summary.
