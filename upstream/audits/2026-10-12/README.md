## Source fidelity

The initial classification of portable tools and guides as transport exclusions
was too broad. Three full-content Sol audits read all 167 source resources and
identified avoidable losses. This candidate restores applicable source sentences,
playbook steps, principles, briefs, guide explanations, optional resources and
portable scripts. Capacity never reduces the method's requirements.

The changes include ketchup, prompting recipes, delegate routing, two-seat
panels, xhigh defaults, the complete planning template, watcher pagination,
current-head readiness checks and PR-target-aware worktree auditing. Comment
Sicko retains its editing role. Code cleanup remains separate from prose cleanup;
CLI/TUI and Electron verification retain their actual driver requirements.
Privacy, worker reconciliation, push cadence and original cleanup gates remain.

Only T3 mechanisms, accounts, installation paths and the existing approved
UPSTREAM.md deltas differ. The user explicitly retained review-it/write-pr and
Autopilot PR timing exceptions. Missing usage automatically attempts an eligible,
confirmed mapping within the authorized policy, preserving pins, billing pools,
effort, panel count and diversity. Retries retain exclusions and inspect prior
writes before another writer starts.

## Portable policy, native transport

The original orchestration store retains its atomic writes, lock ownership,
rename-based inbox drain with rollback, exact PR/SHA ledger and plain formats.
The T3 frontier resolver consumes complete native linked-PR chains, validates
scope and generation, checks fresh GitHub facts and local SHAs, then lets the
existing locked store perform the write. Pins validate discovery, never replace
it. A missing source or contradiction fails without advancing the generation.

The public PR launcher now evaluates one bounded step. It reuses the official
reader, readiness classification and queue state machine. Frozen queues, partial
sweeps, error counts, backoff and deadlines persist in the JSON continuation.
Only native watch tools provide wakes. Status-only exit zero and nonterminal
WAITING are not merge-ready. No evaluation grants merge authority.

The worktree audit retains the full Git inventory, including detached worktrees,
merge-base and squash-PR evidence, WIP versus scratch, remote columns, original
four-day floor, bucket precedence and size ordering. Complete project-scoped T3
history replaces transcript files. Missing pages or text produce unknown evidence
and review, not permission to prune. The audit never deletes worktrees.

See the installed [T3 tool contracts](../../../skills/poteto-mode/references/t3-tools.md)
for input schemas, exports and continuation handling.

## Remaining limitations

T3's native watch reports that it stops after eight consecutive internal read
failures, but exposes neither that counter nor its last successful read. The
one-shot evaluator preserves the official five-error default for its own GitHub
queries. Native wakes do not guarantee the official polling, sweep, backoff or
deadline timing. Keep those budgets; never interpret silence as readiness or add
a polling process. Complete transport parity requires native telemetry and wake
controls that are not currently exposed.

The optional Benny pack retains all reproduction, tracker, Slack-thread,
verification, configuration and budget contracts. A supported equivalent to the
reviewed Automations editor handoff and per-automation child-write isolation has
not been demonstrated. Backend schedule creation is not a substitute. Nothing
activates Benny, posts to Slack or alters the user's existing issue workflow.

Required child worktree/process isolation and Electron CDP control remain factual
runtime prerequisites. Top-level conversations require explicit user requests.
The conditional Origin recipes remain; no Origin executable was available here.
The ACP bridge was absent, so ACP validation is contract-only until a supported
runtime supplies it. No private T3 database or undocumented transport is used.

Official unslop changed. Update it separately through Skills CLI from the pinned
official revision after installation approval. This candidate changes neither its
fork copy nor any third-party installed skill.

original store, watcher and plan cases; permanent T3 cases exercise frontier
